# v2 pre-RC code review (started 2026-09-23)

Tracks the code review that gates `v2.0.0-rc1` (Phase 6.6 in
[`v2-progress.md`](./v2-progress.md)). One section per round; each
finding gets a status and, when fixed, its commit.

## Why this scope

Dogfooding on 2026-09-23 found three bugs in about twenty minutes, all at
v1 ↔ v2 seams rather than in algorithms:

| Commit | Bug | Seam |
|---|---|---|
| `14e6a66b` | Translate page before inpaint → "Renderer ran but produced no output" | v2 engine hard-errors on a result the v1 facade returned silently |
| `fe09561c` | Click a text box after OCR → "Nothing to render" | UI auto-fires an RPC without its preconditions; `render` errors surface as a dialog |
| `8ace0884` | Text box handles float over the Welcome gate after Close project | Canvas z-indices not scoped to the canvas |

So the review is **diff-driven**: the unit of review is
`git diff origin/main...HEAD` (excluding `third-party/cudarc`) — about
13.3k added Rust lines in 83 files and 3.8k TS lines in 32 files, ~22% of
the codebase. From each changed entry point, trace outward into the v1
code it calls; v1 code with no v2 caller is out of scope (it shipped in
1.2.x).

## Method (every round)

1. Trace real code paths from the diff, not file by file. Every suspicion
   needs a concrete failure scenario.
2. Reproduce before fixing: a failing test, an e2e spec, or exact app
   steps. No repro → log it as *suspect*, do not fix.
3. One commit per bug, with a regression guard: Rust test, or an
   e2e spec for UI bugs (the UI has no unit-test setup). Gate:
   `cargo fmt --check`, `clippy --workspace --all-targets -D warnings`,
   `cargo test --workspace`; `tsc` clean in touched files.
4. Close the round: build, owner smoke-tests on the RTX 5070 box, record
   found / fixed / deferred below.

A round is done when every changed entry point in its scope has been
traced and every finding is fixed, deferred with a reason, or marked
not-a-bug.

Round 1 comes before the engine seam because migration is one-way and has
already run on a real project (TEST2); data loss cannot be undone, error
dialogs can.
